# 2026-10-23: required Rust calculation core (0.3.0)

## Scope and existing routes

There was no Rust implementation in this repository. The existing temperature
adapter and Japanese/English forecast paths now call one required Rust core for
temperature differences, inclusive 7-degree classification, rain-code detection,
hourly rain classification, and heat categories. Their Python calculation bodies
were removed. ctypes validates Python values and marshals a primitive C ABI;
it is not a Python calculation fallback. Missing/incompatible native code fails
on import with a rebuild instruction. No weather requests run in the background.

MCP's official Python SDK, httpx, ZoneInfo date/time handling, Unicode summary
formatting, geocoding, and atomic flock-protected location persistence remain
Python. Migrating those requires replacing protocol, timezone, HTTP and storage
boundaries and validating their full cross-platform behavior. They are not
covered by this pure-computation migration; this is not an all-Rust server.
The remaining HTTP path still requires certifi >= 2026.10.19; pip >= 26.2.2 when
present, and uv >= 0.13.4 remain mandatory as documented in the security note.
The Rust core has no external crates, TLS, I/O or CA bundle.

## Pytra evaluation and rejected output

Shared read-only source: `/Applications/Pytra`, clean commit
`9f341e04fefd8eacac1081c59e80f4042ee80a6f`. No clone/download was made here.
Read README, the Python differences tutorial and the actual CLI help. The
wrapper is not executable and the system Python 3.11 cannot parse its Python
3.12 type aliases. Evaluation used Python 3.14, PYTHONDONTWRITEBYTECODE=1,
PYTHONPATH pointing at the shared src, and a dedicated `work/pytra/runner`
working directory whose src symlink points at the shared src. This avoids the
compiler's cwd-relative profile lookup and shared work/tmp writes.

From that runner directory (substitute the absolute project path):

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=/Applications/Pytra/src python3.14 \
  /Applications/Pytra/src/pytra-cli.py -build \
  /absolute/project/src/home_weather/temperature.py \
  --target rs --rs-package --opt-level 0 -o /absolute/project/work/pytra/original
cargo check --manifest-path /absolute/project/work/pytra/original/Cargo.toml --offline
```

The input was the version at security checkpoint `9bddbff`. Emission succeeded,
but inspection of the complete generated temperature function found:

- numeric isinstance became `(false || false)`;
- subtraction became `todo!("Box<dyn Any> arithmetic: Sub")`;
- the result dictionary disappeared and the function returned unit;
- unsupported cloning/comparison of Box<dyn Any>;
- imports of absent pytra_built_in_error and pytra_std_re modules.

Cargo check failed with seven errors. The generated code and runtime are **not
shipped**. The replacement is handwritten MIT Rust; no Pytra-generated/runtime
code is included, so no Apache code was added to the distribution. No shared
Pytra source was changed. Generated evaluation output stays under ignored work/.

## Review and semantics

All handwritten Rust and ABI adapter code was reviewed. Arguments/results use
fixed numeric types; there are no borrowed pointers, shared mutable state,
unsafe Rust blocks, cross-boundary allocations or object ownership transfers.
UTF-8 strings remain with Python's existing Unicode formatting. Native code
uses finite checks and decimal formatting (round-to-nearest, ties-to-even) for
the former round(delta, 10). Missing values/bools remain unknown for temperature;
a numeric NaN is distinct from a missing rain value using an explicit mask.
Hourly filtering, interval merging, Tokyo defaults, MCP schemas and location
writes retain their existing implementations and regression tests.

Two intentional malformed-input changes are explicit: a finite subtraction
that overflows now yields unknown instead of infinity/true; integers or integer
differences outside exact binary64 range (2**53) raise ValueError rather than
silently losing precision. Physical weather inputs are far within that range.

## Build, distribution and checks

Source installation requires cargo on PATH (verified Rust 1.99.1). `uv sync
--frozen` builds a platform-specific native library through hatch_build.py.
`uv build` rebuilds the wheel from the sdist, which contains Rust sources and
Cargo.lock. Build uses --locked --offline: the Rust core has zero dependencies.
Wheels are platform-specific, not universal; tested macOS 26 arm64. Do not copy
a macOS wheel to Linux. CI builds Linux/macOS and Python 3.11/3.14 from source.
Existing installations need `uv sync --frozen --reinstall-package home-weather-mcp`
and a client MCP reload. Existing location settings are unchanged.

Performance: local Python 3.11, minimum of five runs of 100,000 temperature calls:
old Python 0.0411 s; Rust via ctypes 0.0690 s. The FFI adapter is slower for this
small scalar operation (~0.28 microseconds extra per call), so no speedup is
claimed. Network latency dominates on-demand weather calls. This migration is
for the requested implementation language, not an observed latency improvement.
