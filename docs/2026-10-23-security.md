# 2026-10-23: emSign CA incident update

The Python security advisory requires certifi >= 2026.10.19, pip >= 26.2.2,
and uv >= 0.13.4. The former certifi 2026.7.22 lock and uv 0.10.2 CI pin
are removed. Project metadata enforces uv's minimum version; WeatherAPI
rejects an older certifi before constructing an HTTP client. TLS verification
remains enabled. No compatibility fallback to the old bundle is provided.

Source: https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576

## Existing installations

Do not use an old pip/uv to fetch arbitrary upgrades. Bootstrap pip using the
advisory's exact wheel and SHA256, in a dedicated temporary environment:

```sh
python3 -m venv /tmp/weather-tools
/tmp/weather-tools/bin/python -m pip --disable-pip-version-check install 'pip @ https://files.pythonhosted.org/packages/3f/06/3e4420302363fbb71be3c7f35ce042f54bfca330e3e66b3a2e3c4cca579f/pip-26.2.2-py3-none-any.whl#sha256=fd7f4dfa8190e014013b9f08f3e973f4e4c26ffd179a204895533a7254813a70'
/tmp/weather-tools/bin/python -m pip install 'uv==0.13.4'
/tmp/weather-tools/bin/uv sync --frozen
/tmp/weather-tools/bin/uv run --frozen python scripts/check_security.py
```

If the project environment contains old pip or uv, recreate that environment
using the safe uv above, or upgrade those tools explicitly. A normal uv-created
project environment does not contain pip. Retain locations.json outside the
virtual environment. Reload the client's MCP process after updating; existing
processes are not automatically restarted. Update the host's CA store as well.

## Validation

Local Python 3.11: full pytest suite, package build, scripts/check_dist.py,
and scripts/check_security.py. The unsafe-bundle regression verifies rejection
before HTTP client creation, including prerelease versions below the minimum.
Linux and Python 3.14 are covered by CI, not claimed as locally executed.
No live weather requests or personal configuration changes are required.
