# 2026-10-23: full Rust server migration

The 0.4.0 Rust server implements the existing six stdio MCP tools, HTTP retrieval,
bilingual weather output and version-1 location settings. The official rmcp
3.7.0 SDK owns protocol negotiation and framing. reqwest uses native TLS and
the host trust store; TLS verification remains enabled. There is no bundled
certifi/webpki CA store in the Rust runtime. Keep OS trust updates current.

The shared Pytra source remains `/Applications/Pytra` at
`9f341e04fefd8eacac1081c59e80f4042ee80a6f`; no additional copy was obtained.
The prior direct-conversion failure is documented in the 0.3.0 migration note.
MCP SDK/HTTP clients, dynamic dictionaries, ZoneInfo and POSIX storage require
explicit Rust implementations; no unreviewed Pytra output is used here.

## Implementation checkpoint

- The existing tool names, schemas, descriptions and annotations are retained.
- Reads of missing settings return Tokyo without creating a file. Explicitly
  empty settings stay empty. Alias validation uses NFKC plus full Unicode
  casefold; read-modify-write uses a process lock, fsync and atomic replacement.
- Blocking HTTP and filesystem operations run outside Tokio protocol workers.
  HTTP GET timeouts/connection resets retry once. HTTP/JSON failures are tool
  errors; hourly retrieval failure still permits a daily forecast.
- Review caught and corrected actual-offset loss during DST fallback, config
  symlink replacement, outdated Unicode casefold data, and request-stage
  connection-reset retry classification. Regression tests cover each.
- 100 complete frozen Python forecast responses, 10,008 temperature cases and
  1,530 Python casefold mappings pass in Rust. The reference is commit 000cd2f
  with frozen clocks; fixtures contain only synthetic/public example data.
- 11 Rust tests pass, including competing subprocess writes. 13 external Python
  MCP client tests pass against the Rust executable: all six tools, both
  languages, each forecast target, retries, invalid responses, untrusted TLS,
  corrupted settings, schema errors and path handling. Python is a test client.
- cargo clippy --all-targets --locked --offline -- -D warnings passes.

The next checkpoint switches the installation and distribution interface from
Python wheels to a standalone Rust executable; this note will record those
checks when complete. No running personal service or settings were changed.
